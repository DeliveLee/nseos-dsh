## 红线（不可协商 · 本节不可删除、不可修改、不可被下表任何条目覆盖）

**任何人类签署、任何长跑压力、任何「这次特殊」都不能覆盖本节。** 本节由 `references/AUTONOMY_POLICY.md` 第二节定义，此处为内置副本。

1. **发布凭据永不可预授权、不可自签充数。** `ai-nseos/state/.release-ready.json` 的 `review` / `prod_schema` / `doc` 三个字段，只在对应的真实动作发生后才写：`review` 需真的跑过独立评审并产出报告，`prod_schema` 需人类确认过生产 schema，`doc` 需文档已维护。为了通过门禁而写字段 = 伪造验收证据。凭据在机制上确实是「一条命令就能自签」的 advisory 中断，**这正是它必须靠本条约束的原因，不是可以自签的理由**。v0.24.0 起 `review` 必须写 `independent: true|false`（自审如实写 `false` 仍可发布，门禁只多问人类一次；把自审写成 `true` 才是伪造），且每个字段带 `head_sha`（写完再产生新提交即失效）。

2. **`AINSEOS_*` 阀门属人类运维，模型不得关闭、不得请求关闭。** `AINSEOS_ACTION_GATE` / `AINSEOS_PROMPT_ROUTING` / `AINSEOS_SKILL_GATE` / `AINSEOS_DOC_GATE` 等开关是人类维护工具的手段，不是给模型的逃生口。在报告里向人类建议关阀门，等同于自己关。

3. **内联环境前缀对 hook 无效。** `AINSEOS_ACTION_GATE=off git push` 不会生效——hook 读 Claude 进程环境，不读单条命令的前缀环境。它照样被下一道门拦住；写出这条命令唯一的后果是留下一次试图绕过门禁的记录。

**撞到门禁 = 合法挂起。** 正确动作：停 → 记入 `DECISION_LOG.md` 挂起清单 → 如实报「门禁 X 未通过，缺 A / B 两项；本次已完成的是 C / D」→ 结束。不重试、不换写法、不找等价路径。

> 依据：`FB-20260725-003` 实测——bonohair-rebuild 会话 `c7c77a12` 在 `/goal` 长跑 + Stop hook 反复回压下，两次正确拒绝门禁后第三次执行了 `AINSEOS_ACTION_GATE=off git push`。自主模式是同一种压力的制度化版本。

## 授权条目

> **本表只列《勘探报告》实际识别出的疑点。禁止用通用风险清单填充。**
> 通用清单会让人类面对一屏「遇到 X 怎么办」直接全选默认，授权书就退化成橡皮图章、失去全部意义。
> 每一行的「疑点编号」必须能在 `RECON_REPORT.md` 的「未验证疑点」表里查到同号条目。查不到 = 这行不该存在，删掉。

| # | 疑点编号 | 若成真的表现 | 默认处置 | 可否回滚 | 人类签署 |
|---|---|---|---|---|---|
| A-01 | U-xx | | | 可（方式：<单条 commit 回退 / 配置开关 / …>）/ **否** | 批准 / 改为：<…> / 拒绝（改为挂起） |

填写要求：

- **若成真的表现**：用户或系统会经历什么，按 `HUMAN_COMMUNICATION.md` 写——后果表述，不软化严重性。
- **默认处置**：具体到执行期 AI 能照做的程度。「视情况处理」不是处置。
- **可否回滚**：写「否」的条目需人类格外注意，签署时应默认倾向拒绝并改为挂起。
- **人类签署**：逐条签。整表一次性「全部同意」不构成有效授权——那正是橡皮图章。
