# Task Ledger（任务账本）: <TASK-ID> — <Title>

这个任务「还剩多少」的**唯一权威答案**。一行一条、状态可数。

**为什么每个任务都有一份，而不是只有长任务有**（v0.32.0，用户裁决）：判断「这算不算长任务」两个方向都错——判轻了漏掉真出事的会话，判重了在正常会话里误拦。让每个够得上门槛的任务都带一份，判断问题就整个消失了。门槛是**测量出来的**（本会话动了 ≥3 个不同文件），不是声明出来的：出事那次的流程标记上自己写着 `"mode":"lightweight"`，而它跑了 8 小时 25 分、动了几十个文件。**任何按自我声明的标签给的豁免，都是会话自己发给自己的豁免。**

**它防的那件事**：把「这一批 / 这一棒做完」诚实地报成「整件事做完」。散文式的进度记录做不到这一点——散文不会失败，过期的散文和准确的散文长得一模一样。

## 头部（生成时写入，不手改）

```yaml
task_id:        <任务标识；与流程标记的 contract 对得上>
generated_at:   <UTC 时间戳>
generated_head: <生成时的 git HEAD sha>
source:         <这份账本从哪里生成 —— 功能合同的验收标准 / 计划文档 / 交接单；范围散文的真源>
parent_plan:    <若本任务是某个更大计划的一批，写那个计划的路径；否则写 SELF>
staleness_cmd:  <一条命令：这份账本过期时必须非零退出>
```

**`parent_plan` 是这份模板里最容易被跳过、而代价最大的一行。** 出事那次的会话接手的是一份交接单，它把交接单那 4 件事做完，然后报「没活了」——而那 4 件事是 8 阶段计划里的一小块。**交接单是一个批次，不是目标。** 这一行就是防它。

**`staleness_cmd` 不许留空。** 一份建了却不再刷新的账本会**自信地报一个过期数字**，比没有账本更糟——没有账本时人还知道要自己查，有一份过期账本时人会相信它。最省事的形态：比对 `generated_head` 与当前 HEAD，超出即非零退出。

## 条目表

| # | 条目（做到什么算完，一句话） | 怎么验（能跑出结果的命令或文件） | 状态 | 挂起原因 |
|---|---|---|---|---|
| 1 | <...> | <...> | 红 / 绿 | — |
| 2 | <...> | <...> | 红 | 等人类裁决：<...> |

**状态只有红 / 绿两种**，不许有「进行中」「大概好了」——那些是散文，数不出来。

**「挂起原因」非空 = 这一条不算「可推进」。** 收尾时要报的两个数字由此得出：

```
剩余未完成 N = 状态为红的条目数
其中可推进 M = 红且「挂起原因」为空的条目数
```

`M = 0` 是完全正常的答案——它意味着剩下的都卡在人类身上，如实报出来即可。

## 收尾时怎么用

会话说「做完了 / 没有可推进的活」之前，读这份账本、报出 `N / M`。机器侧由 `Stop` 事件的账本门兜着：出现这类结论而本段没读过账本时，它会拦一次要这两个数字。

## 诚实边界

- **没有任何 hook 会检查这份账本的内容对不对**，也不会检查 `staleness_cmd` 真的会失败、或 `parent_plan` 填得对。门只能看出「账本没被读过」。
- **它数得准不准取决于建它的那一次盘得准不准。** 一份漏了半个计划的账本，会让收尾报出一个自信的错数字。
- **人类可以拒绝建账本**：在流程标记里写 `"goal_source":"NONE"`（整个仓库不要则把 `PROJECT_PROFILE.md` 的 `Progress source:` 写成 `NONE`）。那之后门彻底安静——**但那句「做完了」也就再没有任何东西能替他核对**，拒绝之前必须把这句话说给他听。
